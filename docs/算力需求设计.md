# 未来算力需求设计

**项目**：多智能体 + 提示词自动优化 · 螺丝/螺母工业质检
**关联**：AUP Learning Cloud 云端演示 / 产线部署预估
**数据来源**：本机实测基准（见第 2 节），非经验估计。

---

## 1. 算力构成拆解

本系统的算力消耗由**两段**决定，二者特征完全不同：

| 阶段 | 性质 | 算力类型 | 是否瓶颈 |
|---|---|---|---|
| 感知层（经典 CV：模板差分 + 连通域 + 轮廓几何） | 确定性计算 | CPU | 是（唯一本地计算热点） |
| 决策层（缺陷分析 / 分级 / 反思 Agent） | 规则判定或 LLM 推理 | CPU（模拟器）或 网络 API（真实 LLM） | 取决于是否接云端 LLM |

关键结论：**感知层是唯一稳定的本地计算负载，且极轻**；决策层若用内置确定性模拟器几乎零成本，若接云端 LLM 则瓶颈转移到网络与 API 配额（算力在服务商侧）。

---

## 2. 实测基准（本机，单核 CPU）

运行环境：Python 3.13，OpenCV（headless），Intel 系列 CPU，内置模拟器模式。

| 指标 | 数值 |
|---|---|
| 感知层单件耗时 | **1.42 ms** |
| 全链路单件耗时（感知 + 2 个决策 Agent，模拟器） | **1.62 ms** |
| 等价吞吐 | **≈ 615 件/秒 ≈ 221 万件/小时（单核）** |
| 全链路单核 CPU 占用 | **≈ 0.2%（即 99.8% 空闲）** |

> 含义：在模拟器模式下，单枚 CPU 核心即可轻松支撑绝大多数产线节拍；系统算力需求几乎可以忽略，主要价值在**算法与闭环**而非堆算力。

## 3. 不同部署形态的算力需求

### Tier A — 教学 / 云端演示（当前形态）
- **配置**：1 vCPU，无 GPU，内置模拟器。
- **适用**：AUP Learning Cloud 的 JupyterLab 演示、课程答辩。
- **结论**：平台最低配算力即可流畅运行（Gradio 三页签 + 优化闭环），无需申请额外资源。

### Tier B — 产线离线部署（固化优化后的提示词）
- **做法**：把 `run_experiment.py` 产出的 `optimized_prompt.txt` 固化进分析 Agent，决策全走确定性判据，不再调用 LLM。
- **配置**：2–4 vCPU（多进程并行），无 GPU。
- **吞吐**：感知层可线性扩展。按单核 615 件/秒估算，4 核可达 **~2000 件/秒 ≈ 720 万件/小时**，足以覆盖高速产线（≥ 60 件/秒）数个量级。
- **结论**：**纯 CPU 即可满足绝大多数真实产线**，这是本方案相比「每帧都调大模型」的核心成本优势。

### Tier C — 接云端大模型 API（增强语义理解）
- **瓶颈转移**：每件的决策延迟由「API 往返时延」主导（通常 200–800 ms/次调用，串行 2 次调用即 0.4–1.6 s/件），**算力在 LLM 服务商侧，不在本机**。
- **本机需求**：极低（仅拼接请求/解析响应），1 vCPU 足够。
- **约束**：受 API QPS 配额与网络带宽限制；高吞吐产线需**异步批处理 / 流水线化**，或改用本地小模型（Tier D）。
- **成本口径**：按 token 计费，与本地算力无关，需在预算中单列。

### Tier D — 接本地 VLM / 预训练异常检测（感知升级）
- **触发**：若要放弃「夹具定位 + 模板差分」，直接处理姿态多变、无模板的真实工件（如 MVTec 全品类），感知层需替换为 PatchCore / PaDiM 等模型。
- **配置**：≥ 1 × 入门级 GPU（如 NVIDIA T4 16GB 或同档），决策层仍可用 CPU。
- **吞吐**：受 GPU 推理与预处理拖累，典型 20–200 件/秒（取决于分辨率与模型），仍远高于多数产线节拍。
- **结论**：**GPU 仅在「感知升级」时才必要**，是未来按需扩容点，而非当前必需。

## 4. 产线节拍对照表（帮助选型）

| 产线速度 | 件/秒 | 单核是否够（模拟器/Tier B） | 建议配置 |
|---|---|---|---|
| 慢速（精密件） | 1 | ✅ 富余（占用 <0.2%） | 1 vCPU |
| 中速（通用件） | 10 | ✅ 富余 | 1–2 vCPU |
| 高速（标准件） | 60 | ✅ 富余 | 2–4 vCPU（多进程） |
| 超高速（芯片/零件） | 300+ | 需并行 | 4–8 vCPU 或 Tier D 轻 GPU |

---

## 5. 未来算力扩展路线

1. **短期（课程/演示）**：AUP Cloud 1 vCPU，模拟器模式，零额外算力成本。
2. **中期（产线试点）**：本地 2–4 vCPU + 固化提示词，纯 CPU，免 GPU、免 API 费用。
3. **长期（多品类/无模板）**：引入本地轻量 VLM 或异常检测模型，按需上 1× T4 级 GPU；决策层仍走优化后的确定性判据，保证可解释、可审计。
4. **弹性策略**：若接入云端 LLM，采用「热路径用固化判据保吞吐、冷路径用 LLM 做疑难样本复核」的混合架构，兼顾成本与能力上限。

---

## 6. 一句话结论

> 本方案**当前形态几乎不消耗算力**（单核 1.6 ms/件、CPU 占用 0.2%），可在 AUP Learning Cloud 最低配流畅演示；真正的算力投入应按「是否升级感知（GPU）」「是否接云端 LLM（API 配额）」两个开关按需开启，而非一开始就必须堆硬件。
